# Desktop Spider — архитектура и план

Процедурный паук на Rust, живёт поверх всех окон macOS и бегает за курсором.

---

## 1. Что в видео

Ролик: 33 с, 720×1280 (вертикальный). Это запись скрина из **TouchDesigner**: в конце видны ноды `project1`, `perform`, `Spider`, `KEY_1_RESET`.
Анимации нет, существо собрано **процедурно**: тело + ноги на инверсной кинематике (IK), ноги переступают сами.

| Элемент | Как устроен |
|---|---|
| **Тело** | Маленький прямоугольник с яркой точкой («головой»). Поворачивается по направлению движения. |
| **Курсор** | Вокруг него тусклое кольцо: это **радиус прибытия**. Паук подбегает к краю кольца и останавливается, на сам курсор не лезет. |
| **Ноги** | 8 штук (4 пары). У ног 2–3 сегмента, на суставах точки, колени вывернуты наружу. Ступня стоит на месте, пока тело не отъедет далеко, потом **переступает** на новую точку с упреждением по скорости. |
| **Цели ступней** | Тусклые кружки у концов ног. Это отладочная отрисовка точек, куда ступня шагнёт. |
| **Варианты (пресеты)** | 1) синий, 3 сегмента, плотный; 2) пурпурные **щупальца**: длинные изогнутые цепочки из многих сегментов (FABRIK или верлет); 3) розово-зелёный «долгоногий», 2 сегмента, высокие колени; 4) красный «сенокосец» с редкими длинными ногами; 5) розовый «осьминог»: 5 пунктирных изогнутых щупалец. |
| **Стиль** | Тонкие линии 1–1.5 px, точки на суставах, тёмный фон (у нас он станет прозрачным). |

Вывод: нужна одна конфигурируемая модель «тело + N ног × M сегментов + походка» и несколько пресетов поверх неё.

## 2. Стек

| Задача | Крейт |
|---|---|
| Окно и цикл событий | `winit` 0.30 |
| GPU-рендер | `wgpu` (Metal-бэкенд) |
| Математика | `glam` (`Vec2`) |
| Нативные настройки окна macOS | `objc2`, `objc2-app-kit`, `objc2-foundation` |
| Иконка в меню-баре | `tray-icon` + `muda` |
| Конфиг и пресеты | `serde` + `toml`, `notify` для hot-reload |
| Сборка `.app` | `cargo-bundle` |

Почему wgpu, а не CPU-растеризация (tiny-skia и т.п.): оверлей занимает весь экран, на Retina это 5–6 Мпикс. Перерисовывать их на CPU 120 раз в секунду дорого, а GPU рисует пару сотен отрезков почти бесплатно.

## 3. Архитектура

```
desktop_spider/
├─ Cargo.toml
├─ presets/                 # *.toml — пресеты существ
│  ├─ spider.toml
│  ├─ tentacle.toml
│  └─ harvestman.toml
└─ src/
   ├─ main.rs               # bootstrap, winit ApplicationHandler
   ├─ app.rs               # App: окна, часы, fixed-timestep цикл
   ├─ platform/
   │  ├─ mod.rs
   │  └─ macos.rs           # уровень окна, click-through, Spaces, курсор, экраны
   ├─ sim/
   │  ├─ mod.rs
   │  ├─ creature.rs        # Creature = Body + Vec<Leg> + Gait
   │  ├─ body.rs            # стиринг: seek/arrive, поворот, покачивание
   │  ├─ leg.rs             # состояние ноги: Planted / Stepping, цель, анимация шага
   │  ├─ gait.rs            # группы походки (тетрапод), правила «кто может шагать»
   │  ├─ ik.rs              # two_bone_ik (аналитика), fabrik (N сегментов)
   │  └─ brain.rs           # поведение: chase / idle-wander / sleep / flee
   ├─ render/
   │  ├─ mod.rs
   │  ├─ renderer.rs        # wgpu device/surface, прозрачный swapchain
   │  ├─ batch.rs           # DrawList: segments, dots, rings → instance buffer
   │  └─ shapes.wgsl        # SDF-капсулы и круги с AA
   ├─ config.rs            # Preset (serde), загрузка, hot-reload
   └─ tray.rs              # меню: пресет, пауза, debug, выход
```

### Поток данных за кадр

```
NSEvent.mouseLocation ──► Brain (цель) ──► Body (steering) ──► Legs (step logic + IK)
                                                                     │
                                         DrawList (линии/точки) ◄────┘
                                                │
                                      wgpu instanced draw ──► прозрачное окно
```

- **Симуляция** идёт с фиксированным шагом (120 Гц, аккумулятор), чтобы поведение не зависело от FPS.
- **Рендер** синхронизирован с vsync (`PresentMode::Fifo`), на ProMotion-дисплеях будет 120 Гц.
- Координаты симуляции хранятся в **логических точках глобального пространства экранов**. В пиксели окна они переводятся только в рендере.

### 3.1 Платформенный слой (`platform/macos.rs`): самое важное

На каждый `NSScreen` создаётся одно окно (на старте хватит главного экрана):

```rust
// winit
WindowAttributes::default()
    .with_transparent(true)
    .with_decorations(false)
    .with_resizable(false)
    .with_has_shadow(false)              // ext macOS
    .with_window_level(WindowLevel::AlwaysOnTop);
window.set_cursor_hittest(false)?;       // клики проходят насквозь
event_loop.set_activation_policy(ActivationPolicy::Accessory); // нет иконки в Dock
```

Дополнительные настройки через `objc2` (у winit для них нет API):

```rust
ns_window.setLevel(NSScreenSaverWindowLevel);         // выше меню-бара и Dock
ns_window.setCollectionBehavior(
    CanJoinAllSpaces | Stationary | FullScreenAuxiliary | IgnoresCycle);
ns_window.setFrame_display(screen.frame(), true);    // frame, НЕ visibleFrame
ns_window.setOpaque(false);
ns_window.setBackgroundColor(Some(&NSColor::clearColor()));
```

Позицию курсора берём через `NSEvent::mouseLocation()` в каждом тике.
- **Разрешения не нужны**: ни Accessibility, ни Screen Recording.
- Начало координат у этого API внизу слева, ось Y нужно перевернуть относительно высоты главного экрана.

### 3.2 Симуляция (`sim/`)

**Body**
```
to_target = cursor - pos
dist      = |to_target|
desired   = normalize(to_target) * max_speed * smoothstep(stop_r, slow_r, dist)
vel      += (desired - vel).clamp_len(max_accel * dt)
pos      += vel * dt
heading   = lerp_angle(heading, atan2(vel), turn_rate * dt)   // только если |vel| > eps
```
`stop_r` здесь тот самый радиус-кольцо из видео.

**Leg**: у каждой ноги есть:
- `hip_local`: точка крепления на теле;
- `rest_local`: идеальное место ступни в системе тела (веер вокруг тела);
- `foot`: текущая позиция ступни в мире;
- `state`: `Planted` или `Stepping { from, to, t }`.

Логика шага:
1. `ideal = body_to_world(rest_local) + vel * step_lead`: упреждение по скорости.
2. Если `Planted` и `|foot - ideal| > step_threshold` и `gait.can_step(i)`, нога переходит в `Stepping { from: foot, to: ideal, t: 0 }`.
3. В `Stepping`: `foot = lerp(from, to, ease(t))`. Подъём ноги в 2D имитируем, сдвигая колено наружу на `sin(πt) * lift`, и/или чуть увеличиваем точку ступни.
4. Пока скорость нулевая и ноги кривые, раз в N секунд делается «доводочный» шаг, чтобы паук выпрямил стойку.

**Gait**
- Тетрапод: группа A = {L1, R2, L3, R4}, группа B = {R1, L2, R3, L4}.
- Нога может шагать, только если ни один её сосед (та же сторона ±1 и пара напротив) сейчас не в воздухе.
- Так получается правдоподобное попеременное перебирание ногами, как в видео.

**IK** (`ik.rs`)
- `two_bone_ik(hip, foot, l1, l2, bend_sign) -> knee`: теорема косинусов. Колено выгибается **наружу** от тела (`bend_sign` зависит от стороны). Используется для 2-сегментных ног (пресеты «долгоногий», «сенокосец»).
- `fabrik(chain, target, iters=8)`: для 3+ сегментов и щупалец. Начальную позу задаём «дугой» наружу, чтобы решение не схлопывалось в прямую.
- Щупальца (пресет 2): FABRIK на 12–20 сегментах + лёгкое верлет-сглаживание. Хвосты отстают и красиво изгибаются.

**Brain**: конечный автомат:
- `Chase`: курсор далеко, бежим к нему;
- `Idle`: курсор внутри кольца, стоим, мелко переминаемся, тело дышит;
- `Wander`: курсор не двигался больше 10 с, гуляем по случайным точкам рядом;
- `Flee` (опционально): курсор резко дёрнули в сторону паука, отпрыгиваем.

### 3.3 Рендер (`render/`)

- Один instanced pipeline. Инстанс: `{a: vec2, b: vec2, radius: f32, color: vec4, kind: u32}`.
- `kind`: капсула (отрезок), круг (заливка) или кольцо.
- Фрагментный шейдер считает SDF до отрезка или круга, `alpha = 1 - smoothstep(-aa, aa, d)`. Получается сглаженная линия любой толщины без MSAA.
- Пунктир (пресет «осьминог»): сэмплируем кривую и рисуем точки (dots) вдоль неё.
- Swapchain:
  - формат `Bgra8Unorm`;
  - `alpha_mode` выбираем из `surface.get_capabilities()`, предпочтительно `PostMultiplied` или `PreMultiplied`;
  - каждый кадр чистим в `(0, 0, 0, 0)`;
  - шейдер выдаёт premultiplied-цвет.
- Опциональное свечение: второй проход с бóльшим радиусом и низкой альфой, без блюра.
- Debug-слой (переключается из трея): кольцо прибытия и цели ступней, как кружки в видео.

### 3.4 Конфиг-пресет (`presets/spider.toml`)


## 4. План работ

### Этап 0. Оверлей (≈ полдня)
- [ ] `cargo new`, winit + wgpu, прозрачное окно на весь главный экран.
- [ ] Click-through, AlwaysOnTop, без Dock-иконки, объединение со всеми Spaces.
- [ ] Рисуется круг в позиции курсора.
- **Готово, когда:** круг ездит за мышью поверх любых окон, включая полноэкранные приложения и меню-бар, а клики проходят насквозь.

### Этап 1. Рендер линий (≈ полдня)
- [ ] `DrawList` + instanced SDF-шейдер: капсулы, круги, кольца.
- [ ] Учёт scale factor (Retina).
- **Готово, когда:** тестовая сцена из 500 отрезков рисуется на 120 FPS и занимает меньше 2% CPU.

### Этап 2. Тело (≈ полдня)
- [ ] Fixed-timestep цикл, `Body` с seek/arrive, поворот, кольцо прибытия.
- **Готово, когда:** прямоугольник плавно подъезжает к курсору и останавливается на краю кольца.

### Этап 3. Ноги, первый паук (≈ 1–2 дня)
- [ ] `two_bone_ik` с изгибом наружу.
- [ ] `Leg` и стейт-машина шага, упреждение по скорости.
- [ ] Gait-группы и запрет шага соседям.
- **Готово, когда:** 8 ног попеременно переступают, ступни не скользят, а при развороте на месте ноги перебираются.

### Этап 4. Подгонка под видео (≈ 1 день)
- [ ] Пропорции, толщины, точки на суставах, покачивание тела, цвета.
- [ ] Debug-слой с целями ступней.
- [ ] Покадровое сравнение с роликом (кадры можно достать через `ffmpeg -vf fps=10`).

### Этап 5. Пресеты (≈ 1–2 дня)
- [ ] `config.rs`: загрузка TOML и hot-reload через `notify` (тюнинг без перекомпиляции).
- [ ] FABRIK для 3+ сегментов, пресеты «синий 3-сегментный» и «сенокосец».
- [ ] Щупальца: многосегментная цепочка + сглаживание, стили `curve` и `dotted`, пресеты «щупальца» и «осьминог».

### Этап 6. Интеграция с macOS (≈ 1 день)
- [ ] Иконка в меню-баре: выбор пресета, пауза, debug, выход.
- [ ] Несколько мониторов: окно на каждый `NSScreen`, паук переходит между экранами. Подписка на `NSApplicationDidChangeScreenParametersNotification`.
- [ ] Энергосбережение: если паук стоит, а курсор не двигается, рендер падает до ~10 Гц или кадры не запрашиваются вовсе.
- [ ] Сборка `.app` через `cargo-bundle`, `LSUIElement = true`, опциональный автозапуск (`SMAppService`).

### Этап 6b. Windows
- [ ] См. раздел 6.

### Этап 7. Живость, опционально
- [ ] Brain: wander, sleep, flee.
- [ ] Паук «прилипает» к краям окон: края берутся из `CGWindowListCopyWindowInfo`, без разрешений, только bounds.
- [ ] Несколько пауков и стайное поведение.

## 5. Риски и подводные камни

| Риск | Решение |
|---|---|
| Окно не поверх полноэкранных приложений | `FullScreenAuxiliary` + `CanJoinAllSpaces` + уровень `NSScreenSaverWindowLevel` |
| Окно попадает в Mission Control / Cmd-Tab | `IgnoresCycle`, `Stationary`, `ActivationPolicy::Accessory` |
| Чёрный фон вместо прозрачного | `with_transparent(true)`, корректный `CompositeAlphaMode`, premultiplied-альфа, clear в `(0,0,0,0)` |
| Перевёрнутые координаты курсора | Единая функция `cocoa_to_sim()`: flip Y относительно `NSScreen.screens[0].frame.height` |
| Ступни «скользят» | Ступня в `Planted` хранится в мировых координатах и ни в коем случае не пересчитывается от тела |
| IK «щёлкает» при полностью вытянутой ноге | Clamp `dist` до `(l1 + l2) * 0.999`, после этого шаг форсируется |
| Расход батареи | Idle-режим из этапа 6, рендер только при изменениях |

## 6. Windows

Кроссплатформенны без изменений: `sim/`, `config`, шейдер, wgpu (DX12/Vulkan), winit, `tray-icon`.
Отдельно пишется только `platform/windows.rs` с тем же контрактом.

| Задача | Решение |
|---|---|
| Поверх всего, клики сквозь | `WindowLevel::AlwaysOnTop`, `set_cursor_hittest(false)` + `WS_EX_TOOLWINDOW \| WS_EX_NOACTIVATE` (`windows-sys`) |
| Без кнопки в панели задач | `with_skip_taskbar(true)` |
| Курсор | `GetCursorPos` → логические точки через DPI монитора |
| Несколько мониторов | Одно окно на весь виртуальный рабочий стол (`SM_XVIRTUALSCREEN` …) |
| Автозапуск | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` |
| Сборка | `.exe`, опционально MSI через `cargo-wix` |

**Главный риск: прозрачная поверхность wgpu.** У DX12 swapchain нет попиксельной альфы для HWND
без DirectComposition, Vulkan на Windows часто даёт только `Opaque`.
Первый шаг: проверить на реальной машине, какой `alpha_mode` отдаёт wgpu.
Запасные варианты:
1. Новая версия wgpu с DirectComposition (`Dx12SwapchainKind::DxgiFromVisual`), если стабильна.
2. Маленькое окно вокруг паука, которое ездит за ним, + `UpdateLayeredWindow` с readback кадра.

Общий код: macOS-расширения в `main.rs`/`app.rs` под `#[cfg(target_os = "macos")]`,
атрибуты окна переезжают в `platform::overlay_attributes()`.
Проверка: `cargo check --target x86_64-pc-windows-msvc` локально, сборка и запуск в CI (`windows-latest`).

## 7. Первый шаг

Этап 0 → этап 3 дают рабочего паука примерно за 2–3 дня. Начинать лучше с этапа 0: прозрачное click-through окно поверх всего — единственная «платформенно-рискованная» часть. Остальное — чистая математика.
